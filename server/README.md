# Сервис Заявок - Серверная часть

## Описание проекта

Серверная часть приложения **Сервис Заявок** представляет собой REST API и WebSocket-сервер, разработанные с использованием **Node.js**, **Express** и **MongoDB** для управления заявками, пользователями, профилями, категориями и уведомлениями. Сервер обеспечивает безопасную аутентификацию, обработку файлов, чат в реальном времени и предоставление статистики по заявкам.

Основные функции:

- **Аутентификация и авторизация**: Регистрация, вход, управление ролями и смена пароля с использованием JWT.
- **Управление заявками**: Создание, просмотр, обновление и удаление заявок с поддержкой загрузки файлов и проверки на вирусы (ClamAV).
- **Чат в реальном времени**: Обмен сообщениями в заявках через WebSocket с поддержкой уведомлений.
- **Управление профилями и категориями**: CRUD-операции для профилей пользователей и категорий заявок.
- **Статистика**: Агрегация данных по заявкам (по статусам и приоритетам) за различные периоды.
- **Логирование и кэширование**: Использование Winston для логов и NodeCache для оптимизации запросов.

## Технологический стек

- **Node.js**: Среда выполнения серверного кода.
- **Express**: Фреймворк для создания REST API.
- **MongoDB / Mongoose**: Хранение данных и управление схемами.
- **Socket.IO**: Поддержка чата в реальном времени.
- **JWT (jsonwebtoken)**: Аутентификация и авторизация пользователей.
- **Bcryptjs**: Хеширование паролей.
- **Multer**: Обработка загрузки файлов.
- **ClamAV**: Проверка загружаемых файлов на вирусы.
- **Winston**: Логирование запросов и ошибок.
- **NodeCache**: Кэширование данных для оптимизации производительности.
- **Morgan**: Логирование HTTP-запросов.
- **Express-validator**: Валидация входных данных.
- **@hapi/boom**: Стандартизированная обработка ошибок.
- **CORS**: Поддержка кросс-доменных запросов.
- **Dotenv**: Управление переменными окружения.

## Структура проекта

- **`server/`**: Корневая директория сервера.
  - **`config.js`**: Конфигурация (например, JWT_SECRET).
  - **`index.js`**: Точка входа сервера, настройка Express и Socket.IO.
  - **`package.json`**: Зависимости и скрипты для запуска.
  - **`src/`**:
    - **`controllers/`**: Логика обработки запросов (`Auth.js`, `Ticket.js`, `Profile.js`, `Category.js`, `Message.js`, `Notification.js`).
    - **`middleware/`**: Промежуточные слои (`authMiddleware.js`, `errorMiddleware.js`).
    - **`models/`**: Схемы Mongoose (`Users.js`, `Roles.js`, `Ticket.js`, `Message.js`, `Profile.js`, `Category.js`, `Notification.js`).
    - **`routes/`**: Маршруты API (`auth.js`, `ticket.js`, `message.js`, `profile.js`, `category.js`, `notification.js`).
    - **`logger.js`**: Настройка логирования с использованием Winston.
  - **`Uploads/`**: Директория для хранения загруженных файлов.
  - **`logs/`**: Директория для хранения логов (error.log, info.log, combined.log).

## Основные эндпоинты

1. **Аутентификация**:

   - `POST /auth/registr`: Регистрация пользователя.
   - `POST /auth/login`: Вход пользователя.
   - `GET /auth/users`: Получение списка пользователей (кэшируется).
   - `GET /auth/user/:id`: Получение пользователя по ID.
   - `PUT /auth/update/:id`: Обновление данных пользователя.
   - `DELETE /auth/delete/:id`: Удаление пользователя.
   - `POST /auth/addRole`: Добавление новой роли.
   - `PUT /auth/change-password/:id`: Смена пароля.

2. **Заявки**:

   - `POST /ticket/`: Создание заявки с загрузкой файлов.
   - `GET /ticket/`: Получение списка заявок (с пагинацией).
   - `GET /ticket/:id`: Получение заявки по ID.
   - `GET /ticket/user/:userId`: Получение заявок пользователя (созданных или назначенных).
   - `PUT /ticket/:id`: Обновление заявки (включая статус и файлы).
   - `DELETE /ticket/:id`: Удаление заявки.
   - `GET /ticket/stats`: Статистика заявок по периодам (день, неделя, месяц, год, кастом).

3. **Сообщения**:

   - `POST /message/`: Создание сообщения в заявке.
   - `GET /message/:ticketId`: Получение сообщений по ID заявки.

4. **Профили**:

   - `POST /profile/`: Создание профиля.
   - `GET /profile/`: Получение всех профилей (кэшируется).
   - `GET /profile/:id`: Получение профиля по ID.
   - `PUT /profile/:id`: Обновление профиля.
   - `DELETE /profile/:id`: Удаление профиля.

5. **Категории**:

   - `POST /category/`: Создание категории.
   - `GET /category/`: Получение всех категорий.
   - `GET /category/:id`: Получение категории по ID.
   - `PUT /category/:id`: Обновление категории.
   - `DELETE /category/:id`: Удаление категории.

6. **Уведомления**:
   - `GET /notification/`: Получение уведомлений пользователя.
   - `PUT /notification/read/:ticketId`: Отметка уведомлений как прочитанных.

## WebSocket-события

- **joinTicket**: Подключение клиента к комнате заявки (`ticketId`).
- **resetNotifications**: Сброс уведомлений для заявки (`ticketId`, `userId`).
- **notificationsReset**: Уведомление клиентов в комнате о сбросе уведомлений.

## Установка и запуск

1. **Установите зависимости**:

   ```bash
   npm install
   ```

2. **Настройте переменные окружения**:
   Создайте файл `.env` в корне проекта:

   ```
   DB_URI
   PORT
   JWT_SECRET
   ```

3. **Запустите сервер в режиме разработки**:

   ```bash
   npm run dev
   ```

4. **Запустите сервер в продакшене**:
   ```bash
   node index.js
   ```

## Конфигурация

- **MongoDB**: Укажите `DB_URI` в `.env` для подключения к базе данных.
- **JWT**: Укажите `JWT_SECRET` в `.env` для подписи токенов.
- **ClamAV**: Настройте сервер ClamAV для проверки файлов на вирусы (порт и хост в `Ticket.js`).
- **Логирование**: Логи сохраняются в `logs/error.log`, `logs/info.log` и `logs/combined.log`.
- **Загрузка файлов**: Файлы сохраняются в `Uploads/` с уникальными именами.

## Оптимизация

- **Кэширование**: Используется `NodeCache` для кэширования списков пользователей и профилей (TTL 10 минут).
- **Ограничение размера запросов**: Express ограничивает тело запроса до 1 МБ.
- **Пагинация**: Реализована для списков заявок (`page`, `limit`).
- **Обработка ошибок**: Стандартизирована с использованием `@hapi/boom`.
- **Логирование**: Winston сохраняет логи в файлы и консоль с временными метками и уровнями.

## Безопасность

- **Аутентификация**: JWT-токены с проверкой в `authMiddleware.js`.
- **Валидация**: Используется `express-validator` для проверки входных данных.
- **Проверка файлов**: ClamAV для защиты от вредоносного контента.
- **Санитизация**: Имена файлов очищаются с помощью `sanitize-filename`.
- **CORS**: Настроен для безопасного доступа с клиентской части.

## Требования

- **Node.js**: >= 18.x
- **MongoDB**: >= 4.4
- **ClamAV**: Для проверки файлов (опционально, настройка в `Ticket.js`).
